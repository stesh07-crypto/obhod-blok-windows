# OBhoD Windows

Windows-клиент OBhoD для персональной «Брони».

## Что сделано

- база: PWDTT, зафиксирован upstream commit `055dce9cf9ab34c29690641c8b8c6891d44c0722`;
- Windows-брендинг `OBhoD` / `OBhoD-Windows-x64.exe`;
- при сборке используется текущая иконка OBhoD из проекта iOS;
- отдельного Deploy-раздела нет;
- обычные `wdtt://` / `qwdtt://config?...` остаются как резерв;
- в «Добавить профиль» можно вставить персональную HTTPS-ссылку Брони вида `https://test-36.ru/sub/...?...`;
- клиент загружает **один** персональный профиль, а не каталог серверов;
- из ссылки/ответа берутся `peer`, персональный `password`, VK-хэши и `workers`;
- если у `peer` нет DTLS-порта, Windows-клиент добавляет `:56000`;
- поле `port` из qWDTT используется как локальный listen-port (по умолчанию `9000`), а не как DTLS-порт сервера;
- повторная вставка той же HTTPS-ссылки обновляет существующую Броню вместо создания дубля;
- данные OBhoD хранятся отдельно от PWDTT (`obhod` / `obhod_*`), чтобы две программы не конфликтовали;
- проверка обновлений upstream PWDTT внутри OBhoD отключена.

## Сборка

Workflow `.github/workflows/build-windows.yml`:

1. забирает точную зафиксированную версию PWDTT;
2. применяет изменения из `scripts/apply_obhod.py` и `overlay/`;
3. ставит актуальную иконку OBhoD;
4. собирает Windows x64 через Wails;
5. публикует artifact `OBhoD-Windows-x64`;
6. отдельно публикует полностью пропатченный исходник как `OBhoD-Windows-source`.

## Как пользователь добавляет Броню

1. В боте копирует свою персональную HTTPS-ссылку.
2. В OBhoD Windows нажимает `+`.
3. Вставляет ссылку в поле «Вставьте ссылку Брони».
4. Программа загружает параметры и показывает «Броня загружена».
5. Нажимает «Добавить профиль» и затем кнопку подключения.

Бот на этом этапе не изменяется.
